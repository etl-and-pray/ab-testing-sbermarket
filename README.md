# Дизайн и анализ A/B-теста: новый алгоритм ETA в СберМаркете

Учебный кейс: как спроектировать A/B-эксперимент для нового алгоритма предсказания времени доставки (вместо фиксированного интервала 20-60 минут) и как проанализировать его результаты.

> **Важно.** В учебной БД нет реального эксперимента: нет разметки test/control, значений ETA и событий воронки. Поэтому проект состоит из двух частей: (1) дизайн эксперимента, (2) отработка методики анализа на доступных данных с искусственным разбиением на группы. Результаты части 2 иллюстративные и **не говорят об эффективности ETA-алгоритма**.

## Часть 1. Дизайн эксперимента

- **Гипотезы:** персонализированный ETA повышает конверсию в заказ и снижает долю неудачных доставок, не снижая средний чек.
- **Единица сплита:** пользователь (`customer_id`), детерминированный хэш; группа назначается при первом показе интервала, чтобы опыт был одинаковым на всех экранах.
- **Метрики:** основная (конверсия в заказ), guardrail (средний чек, доля успешных доставок), диагностическая (точность прогноза ETA, в данных недоступна).
- **Что нужно для настоящего теста:** флаг группы, значения ETA (план/факт), события воронки.

## Часть 2. Анализ на учебных данных

Данные: 6 таблиц учебной БД (клиенты, сессии, заказы, доставки, товары), выгружены в CSV.

**Проверка и очистка данных**

| Проблема | Масштаб | Решение |
|---|---|---|
| Несколько записей о доставке на один заказ | 815 из 1 871 заказов | схлопнуты до одной строки на заказ (успех, если хоть одна попытка успешна) |
| Заказы без позиций в `orders_product` | 315 из 2 950 (10,7%) | исключены из расчётов по чеку |
| Клиенты из заказов, которых нет в `customers` | 5 | оставлены, отмечены |
| Пустая строка в `customers` | 1 | удалена |

**Статистика** (группы построены хэшем `customer_id`, разница ожидаема нулевая)

| Метрика | control | test | p-value | Тест |
|---|---|---|---|---|
| Средний чек, руб. | 479 379 | 514 078 | 0,38 (Манн-Уитни 0,70) | Welch t-test |
| Доля успешных доставок | 63,2% | 62,4% | 0,73 | z-тест для долей |
| Конверсия сессия → заказ | 100% | 98,4% | 0,044 | z-тест для долей |

SRM-проверка пройдена (254 / 247, p = 0,75).

**Вывод.** Значимых различий нет, и это ожидаемо: сплит искусственный. Формально значимая конверсия (p = 0,044) не сигнал: метрика упирается в потолок (почти все клиенты заказывали хотя бы раз), а при трёх проверяемых метриках шанс случайного p < 0,05 около 14%.

## Что показывает проект

Методику, которую можно применить к реальным данным теста: очистка данных, SRM, выбор теста под тип метрики, доверительные интервалы, учёт множественных сравнений.
